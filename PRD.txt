Project Requirements Document

SKILL:  You are a skilled embedded system engineer.  You are knowledgeable in ESP32 Development and Graphics programming with the ILI9431 TFT LCD driver.

Project: ESP32 Tetris Game (SPI TFT + I2S Sound)
Target MCU: ESP32-WROOM (DevKit-style board, Arduino/PlatformIO)
Display: 320×240 TFT LCD with ILI9341/ILI9431-compatible controller (SPI)
Audio: MAX98357A I2S amplifier + 0.5W 8Ω 28mm speaker
Input: 5 momentary push buttons
Language/Framework: Arduino C++ (PlatformIO, VS Code)
Connectivity: No Wi-Fi / Bluetooth; both cores available for app use.

1. Hardware Overview & Wiring
1.1 Power

ESP32 board powered via USB 5 V.

TFT, MAX98357A, buttons powered from 3.3 V rail from ESP32 where possible.

Ensure total 3.3 V current draw stays within regulator specs; otherwise, external 3.3 V regulator.

1.2 TFT LCD (ILI9341/ILI9431) — SPI

Assumptions:

320×240 pixels, SPI interface.

Uses standard SPI lines + DC, CS, RESET, and optional backlight pin.

Pin assignment (example; can be changed but must be consistent in code):

Function	TFT Pin	ESP32 Pin (example)
VCC	3.3 V	3V3
GND	GND	GND
SCK / CLK	SCK	GPIO18
MOSI / SDA	MOSI	GPIO23
MISO (if present)	MISO	GPIO19
CS	CS	GPIO5
D/C or RS	DC	GPIO2
RESET	RST	GPIO4
LED / BL	LED	3.3 V or GPIO15 via transistor (optional dimming)

Notes:

SPI will use VSPI (default: SCK=18, MISO=19, MOSI=23) for performance.

Backlight can be tied to 3.3 V for always-on, or controlled by a GPIO for future dimming/sleep.

1.3 MAX98357A I2S Amplifier + Speaker

Assumptions:

MAX98357A board using I2S input.

Speaker: 0.5W, 8 Ω, 28mm.

Pin assignment (example):

Function	MAX98357A Pin	ESP32 Pin (example)
VIN	5 V	5V from ESP32 USB
GND	GND	GND
LRC / LRCLK	LRC	GPIO25
BCLK	BCLK	GPIO26
DIN (Data In)	DIN	GPIO22
SD / Gain pins	(as per board)	GND / tied as needed

Notes:

Use 5 V for MAX98357A VIN to get full output power.

Speaker connected directly to speaker output terminals of MAX98357A.

1.4 Buttons (5 × momentary)

Functions:

Button A: Pause / Resume Game

Button B: Rotate (each push will rotate the piece to the left for all configurations)

Button C: Translate piece right

Button D: Translate piece left

Button E: Hard drop (immediate descent) of current piece

Electrical:

All buttons wired active low:

One side to GND.

Other side to dedicated GPIO with internal pull-up enabled in software.

Pin assignment (example):

Function	Button	ESP32 Pin
Pause	A	GPIO32
Rotate	B	GPIO33
Translate Right	C	GPIO27
Translate Left	D	GPIO14
Hard Drop (immediate)	E	GPIO13

Debounce required in software.

4. High-Level Architecture
4.1 Core Responsibilities

Core 1 (APP CPU)

Main game logic (piece movement, collision, scoring, levels).

Rendering to TFT display.

Reading debounced button states (can be in this task or separate).

Core 0 (PRO CPU)

Audio/I2S playback task.

Optional: Input task, if you want to isolate I/O timing.

4.2 Tasks

Game Task (core 1):

Runs main game loop:

Polls input state (or reads shared input flags).

Advances game state according to gravity timer and player input.

Detects line clears, level ups, and game over.

Triggers sound events via a thread-safe audio command queue.

Requests display updates.

Display Task (core 1, can be part of Game Task or separate):

Responsible for efficient drawing/updating:

Redraw changed cells only.

Draw next-piece preview.

Draw score/level UI elements.

Audio Task (core 0):

Reads sound commands from a queue (e.g., “ROTATE_SOUND”, “LINE_CLEAR_SOUND”).

Generates and streams audio samples to I2S.

Ensures non-blocking behavior to avoid glitching.

Input Task (optional, either core):

Polls button GPIOs, performs debouncing.

Updates a shared input state structure accessed by Game Task.

6. Game Logic & Mechanics
6.1 Playfield

Grid: 10 columns × 20 rows visible.

Optionally maintain 1–2 hidden rows at top to simplify spawn and collision logic.

Each cell stores:

Empty or occupied.

Color index or 16-bit RGB565 color.

6.2 Tetromino Rules

Standard 7-piece Tetris set (I, O, T, S, Z, J, L).

Random piece selection (simple random; no need for “bag” randomizer for first version).

Rotation:

Rotate around piece center using pre-defined rotation states.

On rotation, if collision with wall/blocks:

Option 1: simple revert (no rotation).

Option 2: basic wall-kick: try shifting ±1 horizontally before giving up.

6.3 Gravity & Movement

Gravity: piece automatically moves down every gravityIntervalMs based on the current level:

Level 0: slower (e.g., 800 ms).

Higher levels: reduce interval progressively (e.g., 50–100 ms per level to a minimum threshold).

Movement:

Left/right movement via button presses.

Hard drop:

On press, move piece down until collision, then step back one row and place immediately.

Trigger place sound, then line clear check.

6.4 Line Clearing & Levels

After piece placement:

Scan playfield for fully occupied rows.

Remove those rows, shift above rows down.

Maintain:

totalLinesCleared integer.

level = totalLinesCleared / 20 (integer division).

On crossing each multiple of 20:

Level increments.

Trigger SOUND_LEVEL_UP.

Adjust gravity interval accordingly.

6.5 Scoring (Optional but recommended)

Provide scoring but not required by user; keep minimal:

1 line: +100

2 lines: +300

3 lines: +500

4 lines: +800

Show score on screen if implemented.

6.6 Game States

PLAYING

PAUSED

GAME_OVER

Transitions:

PLAYING → PAUSED on pause button press.

PAUSED → PLAYING on pause button press again.

PLAYING → GAME_OVER if new piece cannot spawn (collision on spawn).

From GAME_OVER, pressing pause/hard drop could restart game (define restart rule clearly when coding).

7. Input Handling
7.1 Button Mapping

Pause (Button A):

Short press toggles PAUSE/RESUME.

Ignored in GAME_OVER until restart behavior defined.

Rotate Left (Button B):

Trigger SOUND_ROTATE.

Rotate Right (Button C):

On edge trigger (press), rotate current piece right.

Trigger SOUND_ROTATE.

Expose HIGH-level events (pressed) to game logic, not raw pin levels.

9. Audio Behavior
9.1 I2S Setup

Sample rate: 22050 Hz or 44100 Hz (configurable in config.h).

Mono output.

16-bit signed PCM.

Use ESP32 I2S peripheral in TX mode only.

9.2 Sound Events

Define sounds for:

Piece Rotation

Short, subtle blip.

Piece Placement

Slightly stronger “thud” or tone.

Row(s) Completed

Rising short arpeggio or chord.

New Level Achieved

Distinct, upbeat jingle (slightly longer).

Game Lost (Game Over)

Descending tone or “sad” arpeggio.

9.3 Implementation Notes

For each SoundEvent, predefine:

Sequence of frequencies & durations for simple tone synthesis, OR

Precomputed short PCM arrays stored in PROGMEM.

Audio task:

Non-blocking: generate samples in chunks and push to I2S.

Maintain a queue: multiple requests can be enqueued; handle them sequentially.

Volume is controlled by analog stage (MAX98357A); software may avoid clipping by limiting amplitude.

14. Additional Input Device — Analog Joystick

14.1 Purpose

An analog 2-axis joystick with integrated momentary switch shall be added as an
additional control device. The existing five push buttons remain fully functional
and unchanged. The joystick provides redundant and continuous control mapped to
the same in-game actions.

14.2 Electrical Interface & Pin Assignment

The joystick module provides:

- X axis: analog voltage via potentiometer
- Y axis: analog voltage via potentiometer
- SW: momentary push button (active low)

JOYSTICK_Y          GPIO35      ADC1 input, input-only, no pull-up

Power:

Joystick VCC → 3.3V  
Joystick GND → GND

14.4 Logical Control Mapping

Joystick input generates the same logical actions as the push buttons:

UP            → Rotate tetromino
LEFT          → Move left
RIGHT         → Move right
DOWN          → Hard drop


14.5 Analog Interpretation

Centered value ≈ mid-scale ADC reading.

Define a dead-zone around center to prevent drift.

Movement regions per axis:

CENTER ZONE:
No action generated.

SMALL DEFLECTION:
Generate a single movement event on entry into the zone.

LARGE DEFLECTION:
Generate repeated movement events at fixed interval.

14.6 Horizontal Movement Behavior

Small left/right deflection:
- Move exactly one grid cell per entry into the zone.

Large left/right deflection:
- Auto-repeat horizontal movement.
- Repeat interval: 500 ms.

This auto-repeat is independent of gravity timing.

14.7 Vertical Movement Behavior

Upward deflection beyond threshold:
- Trigger rotate (edge-triggered, no auto-repeat).

Downward deflection beyond threshold:
- Trigger hard drop immediately.

14.8 Software Implementation Notes

- Use ADC1 for both axes to avoid Wi-Fi/BT conflicts (even though radios are disabled).
- Sample rate for joystick: 100–200 Hz.
- Apply simple smoothing (moving average or median of last N samples).
- Convert analog values into digital action events in input module.
- Merge joystick-generated actions with button-generated actions into the same
  InputState structure so the game logic remains unchanged.

14.9 Input Priority

If both joystick and button request the same action simultaneously,
they are treated identically. No special priority is required.

Define:

JOYSTICK_SMALL_THRESHOLD
JOYSTICK_LARGE_THRESHOLD
JOYSTICK_REPEAT_INTERVAL_MS = 500

15. Background Music

15.1 Overview

A continuously looping background music track shall play during active gameplay.
The melody is Tetris Theme A (Korobeiniki), the classic Gameboy version, matching
the score at https://musescore.com/user/46143110/scores/12273445

15.2 Melody Specification

Piece:   Tetris Theme A (Korobeiniki) — Gameboy arrangement
Key:     A minor / C major
BPM:     149
Structure: AABB (Part A × 2, Part B × 2) — 16 measures, 77 notes total
Duration per loop: ~1 minute 4 seconds at 149 BPM

Note table (frequency / duration pairs) stored as a static const array of
MusicNote structs in audio.cpp.  The melody loops seamlessly at end.

15.3 Timing

Note durations are derived at compile-time from BPM and sample rate:

Quarter note (Q)  = SAMPLE_RATE × 60 / BPM  samples
Eighth  note (E)  = Q / 2
Dotted quarter (DQ) = Q × 3 / 2
Half note (H)     = Q × 2

An articulation gap of 8 % (NOTE_GAP_RATIO = 0.08) is silenced at the end of
each note to clearly separate consecutive identical pitches.

15.4 Audio Engine

The audio task generates music in chunks of AUDIO_BUFFER_SIZE samples per call
to advanceMusicChunk(), which is invoked every processAudio() cycle.

Sound effects (SFX) interrupt the music stream briefly: one queued SFX is
processed to I2S before the music chunk is written.  Since SFX durations are
short (50–500 ms), the music resumes with negligible audible gap.

When music is paused or disabled, silence buffers are written to keep the I2S
DMA pipeline primed.

15.5 Volume

MUSIC_VOLUME = 5000  (amplitude, 0–32767)   ~30% of SOUND_VOLUME (16000)

This balance ensures game sound effects remain clearly audible above the music.

15.6 Music Control API (audio.h)

void startMusic();   // Reset to beginning and begin playback
void stopMusic();    // Silence; called on game over
void pauseMusic();   // Freeze position; called when game is paused
void resumeMusic();  // Continue from frozen position; called on unpause

15.7 Game Integration (tasks.cpp)

Event                  Action
Game task starts     → audioManager.startMusic()
Player pauses game   → audioManager.pauseMusic()
Player unpauses game → audioManager.resumeMusic()
Game over detected   → audioManager.stopMusic(); enqueueSound(SOUND_GAME_OVER)

15.8 Configuration Constants (config.h)

MUSIC_VOLUME          — amplitude for music synthesis (default 5000)
MUSIC_BPM             — tempo (default 149.0f)
MUSIC_NOTE_Q/E/DQ/H   — compile-time sample counts per note duration
NOTE_GAP_RATIO        — articulation silence fraction per note (default 0.08f)
